Bullet Hell Game Tutorial using Felgo

Introduction

This tutorial describes how to create a simple 2D Bullet Hell Game using Felgo.

The tutorial will provide a base for the overall game, enabling anyone to further expand on it. Here we will go in details on how to implement the player controls and shooting mechanics, enemies, their state machines and attack patterns.

The source code for the finished project is available on GitHub

Assets

The art assets used throughout this tutorial are from Kenney and are available here under CC0 1.0 License. This asset pack doesn't cover all of the needed art, thus some of the missing pieces were hand-drawn in the same style. All of the used art assets are available in GitHub Repository under assets/entities

Project Setup

Start by creating a new Felgo Games project in Qt Creator. Specifically we will need New - Empty Felgo Project template. The created project will already contain some example code in the Main.qml, which we will reduce down to these 15 lines:

import Felgo 4.0
import QtQuick 2.0

GameWindow {
        id: gameWindow
        activeScene: scene
        screenWidth: 960
        screenHeight: 640

        Scene {
                id: scene
        }
}

Player Controls

As the first major step, we will start with the player controller, to get at least something moving on the screen. But before we dive into coding a player controller, we need to prepare our scene.

Firstly, our player is an entity and to be able to work with entities our scene needs an entity manager:

// This `Item` serves as a container for all entities. Any entities created during the game,
// will be added to this container.
Item {
        id: level
}

EntityManager {
        id: entityManager
        entityContainer: level
}

Now that, we have an entity manager, we can start creating our player.

The code for the player will live in qml/entities/Player.qml.

import QtQuick
import Felgo

EntityBase {
        id: player
        entityId: "entity"
        entityType: "player"

        Image {
                id: sprite
                // Place the player sprite right in the center of the entity
                anchors.centerIn: parent.anchors.center
                // Disable smoothing to keep the pixel art crisp.
                smooth: false
                source: Qt.resolvedUrl("../../assets/entities/player.png")
                width: 32
                height: 32
        }
}

And then in our Main.qml we will first import the code from entities folder:

import Felgo 4.0
import QtQuick 2.0
import "./entities"

Finally, add our Player right after the EntityManager, like this:

Scene {
        id: scene

        EntityManager {
                id: entityManager
                entityContainer: level
        }

        Player {}
}

Now lets move on to player controls. The player will rely on physics, that means we first need to setup a PhysicsWorld:

Scene {
        id: scene

        EntityManager {
                id: entityManager
                entityContainer: level
        }

        PhysicsWorld {
                id: physicsWorld
                gravity.y: 0
                updatesPerSecondForPhysics: 60
                velocityIterations: 5
                positionIterations: 5
                debugDrawVisible: false
        }

        Player {}
}

Now that we have the PhysicsWorld, we can add a collider to our player, to turn it into a physics object. We will also make our player sprite a child of the collider. The resulting player code looks like this:

CircleCollider {
        id: collider
        radius: 16
        // Disable rotations caused by collisions.
        fixedRotation: true

        Image {
                id: sprite
                anchors.centerIn: parent.anchors.center
                smooth: false
                source: Qt.resolvedUrl("../../assets/entities/player.png")
                width: 32
                height: 32
        }
}

The final step before player is able to move around the scene, is the actual keyboard controls. Here we will use a TwoAxisController with our 4 movement directions mapped to WASD keys.

TwoAxisController has two properties we are interested in: xAxis and yAxis.

We can use them to provide a velocity vector for the CircleCollider like this:

linearVelocity: Qt.point(axisController.xAxis, axisController.yAxis)

TwoAxisController is only able to notify us about, whenever a button gets pressed or released. However, we want to be able to press and hold a button to move in a desired direction. This requires a bit more bookkeeping. We will need to keep track of which of the 4-direction keys are currently pressed and update that state on each press/release together with manually updating xAxis and yAxis properties of the controller.

Add the bool properties, corresponding to each of the movement directions, at the start of the Player entity:

property bool isMovingLeft
property bool isMovingRight
property bool isMovingUp
property bool isMovingDown

Our TwoAxisController we will lok like this:

TwoAxisController {
        id: axisController
        onInputActionPressed: (actionName) => {
                updateActionState(actionName, true);
                updateMovementAxis();
        }
        onInputActionReleased: (actionName) => {
                updateActionState(actionName, false);
                updateMovementAxis();
        }
        inputActionsToKeyCode: {
                "up": Qt.Key_W,
                "down": Qt.Key_S,
                "left": Qt.Key_A,
                "right": Qt.Key_D
        }
}

Also don't forget to add the speed property to the player entity:

property int speed: 150

And finally the helper functions for state tracking and updating controller properties:

function updateActionState(actionName, value) {
        if (actionName === "up") {
                isMovingUp = value
        }

        if (actionName === "down") {
                isMovingDown = value
        }

        if (actionName === "left") {
                isMovingLeft = value
        }

        if (actionName === "right") {
                isMovingRight = value
        }
}

function updateMovementAxis() {
        let dx = 0;
        let dy = 0;

        if (player.isMovingUp) {
                dy -= 1;
        }

        if (player.isMovingDown) {
                dy += 1;
        }

        if (player.isMovingLeft) {
                dx -= 1;
        }

        if (player.isMovingRight) {
                dx += 1;
        }

        if (dx === 0 && dy === 0) {
                axisController.xAxis = 0;
                axisController.yAxis = 0;
        } else {
                let deltaVectorLength = Math.sqrt(dx * dx + dy * dy);
                let deltaScale = 1 / deltaVectorLength * player.speed;

                axisController.xAxis = dx * deltaScale;
                axisController.yAxis = dy * deltaScale;
        }
}

One final touch. We can set the mirror property of the Image to be computed based on the horizontal speed, so the player sprite gets mirrored when the player moves left.

mirror: collider.linearVelocity.x < 0

For the whole player controller to work, we also need to forward all of the key events from the scene to our TwoAxisController. For that we will first need to expose the TwoAxisController inside the player to an outside world, by creating an alias property:

EntityBase {
        id: player
        entityId: "entity"
        entityType: "player"

        property int speed: 150
        property bool isMovingLeft
        property bool isMovingRight
        property bool isMovingUp
        property bool isMovingDown

        // Expose the controller to an outside world
        property alias controller: axisController
        ...

And forward the events by adding this code in our Main.qml:

Keys.forwardTo: [player.controller]

Player {
        id: player
}

At this point the player should be able to move around the screen.

Level

Now that we have a moving player, we can add a level for the player to move around. Here we will go with a rather simple design, the whole level will be a square-shaped arena and it will be its own entity. The level background is built out of tiles from the asset pack.

The code for it is also rather straightforward:

import QtQuick
import Felgo

Item {
        property int levelSize: 176 * 2
        property int wallThickness: 30
        property int wallCategory: Fixture.Category1

        property alias levelWalls: walls

        // Fill the whole screen with a solid color matching the borders of the background sprite
        Rectangle {
                anchors.fill: parent
                color: "#763b36"
        }

        EntityBase {
                // Display the level background below everything
                id: walls
                width: levelSize
                height: levelSize
                anchors.centerIn: parent

                // Top
                BoxCollider {
                        // Move the top one down a bit, so that it covers the top wall
                        y: 16
                        width: parent.width; height: wallThickness
                        bodyType: Body.Static
                        categories: wallCategory
                }

                // Down
                BoxCollider {
                        y: levelSize - wallThickness
                        width: parent.width; height: wallThickness
                        bodyType: Body.Static
                        categories: wallCategory
                }

                // Left
                BoxCollider {
                        width: wallThickness; height: levelSize
                        bodyType: Body.Static
                        categories: wallCategory
                }

                // Right
                BoxCollider {
                        x: levelSize - wallThickness
                        width: wallThickness; height: levelSize
                        bodyType: Body.Static
                        categories: wallCategory
                }

                Image {
                        smooth: false
                        width: levelSize
                        height: levelSize
                        source: Qt.resolvedUrl("../../assets/entities/levelBackground.png")
                }
        }
}

The colliders here are placed to match where the walls in the background sprite are. If you set debugDrawVisible to true in the PhysicsWorld you will see the next picture:

Then we add it to our scene and also set z to some negative value, so that is appears under everything in the scene:

LevelBackground {
        id: levelBackground
        z: -100
        anchors.fill: scene
}

Now, if you run the game, you will notice, that the player is stuck outside of the level. To fix this, we will change the default Player position to be roughly in the middle of the level:

Player {
        id: player
        x: levelWalls.x + levelBackground.levelSize / 2
        y: levelWalls.y + levelBackground.levelSize / 4 * 3
}

And now, we are done with the level part and can move on to other parts of the game.

Bullets and Shooting

Now the fun part. Here we will finaly start adding bullets, because a bullet hell game without the bullets and bullet patterns isn't a bullet hell.

In this part, we will design reusable components for us to later be able to implement different bullet patterns for the enemies. For example, some of the patterns we will have at the end look like this:

First we will start by creating a new entity. A Bullet:

import QtQuick
import Felgo

EntityBase {
        id: bullet
        entityId: "entity"
        entityType: "bullet"

        property int radius: 4
        property point initialImpulse: Qt.point(0, 0)

        CircleCollider {
                id: collider
                radius: bullet.radius
                bodyType: Body.Dynamic
                groupIndex: -1 // make sure that bullets never collide with each other
                linearDamping: 0.1 // make the bullet slows down overtime
                fixedRotation: true
                fixture.onBeginContact: (other, normal) => {
                        // On collision with anything - destroy
                        bullet.destroy();
                }

                Image {
                        smooth: false
                        anchors.centerIn: parent
                        source: Qt.resolvedUrl("../../assets/entities/bullet.png")
                        width: 32
                        height: 32
                }
        }

        Component.onCompleted: {
                collider.applyLinearImpulse(initialImpulse, collider.body.getWorldCenter())
        }
}

Team Component

Before we go and implement shooting, we have one more thing to take care of. We want the same Bullet entity to be reusable and sharable between both the Player and the enemies.

That means the bullet also has to act differently, based on which entity created it. For example, if the bullet was created by the player, we want it to only collide with the walls and the enemies. If the player were to somehow shoot themselves, the bullet should simply ignore the player. The same is for the enemies.

To solve this, we will introduce our first component. This won't be an EntityBase, rather a simple Item and it will live in the qml/components/ directory.

This component will be called Team.

The idea here is simple. For example, the player and its bullet will belong to the same team and entites on the same team will completely ignore each other (they won't collide, they won't apply damage).

The code for it looks like this (it is just a bunch of properties):

Item {
        // The name of the team, only needed in case of debugging
        property string debugName

        // The category for entities of this team.
        property int entityCategory
        // Categories of entities members of this team are allowed to collide with.
        property int entityCollisionCategories

        // The collision category for bullets.
        property int bulletCategory
        // The mask of collision categories the bullets are allowed to collide with.
        property int bulletCollisionCategories
}

Another key factor is that we will only have two instances of this Team component, placed in the scene. And all of the entities will reference them.

Now we can add both teams to our scene:

Team {
        id: playerTeam
        debugName: "player"
        entityCategory: Fixture.Category2

        // The player can collide:
        // 1. level walls
        // 2. with other players (in case there are many of them)
        // 3. bullets
        entityCollisionCategories: levelBackground.wallCategory
                | Fixture.Category2
                | Fixture.Category4
        bulletCategory: Fixture.Category4

        // Don't include `entityCategory` (`Fixture.Category2`) in the collision mask, so that
        // the player doesn't collide with its own bullets.
        bulletCollisionCategories: levelBackground.wallCategory | Fixture.Category3
}
Team {
        id: enemyTeam
        debugName: "enemies"
        entityCategory: Fixture.Category3
        // Enemies can collide:
        // 1. level walls
        // 2. with other enemies
        // 3. bullets
        entityCollisionCategories: levelBackground.wallCategory
                | Fixture.Category3
                | Fixture.Category4
        bulletCategory: Fixture.Category4

        // Don't include `Fixture.Category3` which is an `entityCategory`, to make sure that the
        // bullets created by enemies, don't collide with other enemies, as well as, the one
        // that created them
        bulletCollisionCategories: levelBackground.wallCategory | Fixture.Category2
}

Now we will need to go and update the player collider, like this:

EntityBase {
        // ...

        property Team team

        // ...

        CircleCollider {
                id: collider

                // ...

                categories: team.entityCategory
                collidesWith: team.entityCollisionCategories

                // ...
        }

        // ...
}

And back in our scene, we need to pass the corresponding team instance to the player:

Player {
        id: player
        team: playerTeam
        // ...
}

Also don't forget to add import "../components" in the Player.qml and import "./components" in the scene file.

Now if you try running the game, you will see that ... nothing has changed. However, we are already a step closer to making the player shoot bullets.

Shooting Bullets

To shoot, the player will have to press and hold the Left Mouse Button. To handle this, we will need to add a MouseArea to our scene:

MouseArea {
        id: mouseArea
        enabled: true
        // Cover the whole scene
        anchors.fill: scene
        // Make sure mouse hover event is reported, even if non of the mouse buttons were
        // pressed/released.
        hoverEnabled: true
        // Hide the cursor. We will have a custom crosshair sprite instead.
        cursorShape: "BlankCursor"
        onPositionChanged: (event) => {
                // handle mouse movement
        }
        onPressed: (event) => {
                // start shooting
        }
        onReleased: (event) => {
                // stop shooting
        }
}

We will also add a crosshair to our scene. For now it will just be a white rectangle. Here we bind x and y to mouseArea.mouseX and mouseArea.mouseY, to make it follow the cursor:

Rectangle {
        id: crosshair
        x: mouseArea.mouseX
        y: mouseArea.mouseY
        width: 8
        height: 8
}

Now we will go back to Player.qml here we will need to reference the crosshair by adding a new property on the player:

EntityBase {
        id: player

        // ...

        property bool isMovingUp
        property bool isMovingDown
        property Item crosshair

        // ...
}

And assign it in the scene:

Player {
        id: player
        // ...
        crosshair: crosshair
        // ...
}

One last think to take care of, is that we need to add a reference to the Team instance in the Bullet entity. From that Team instance we will use earlier described bulletCategory and bulletCollisionCategories.

import QtQuick
import Felgo
import "../components"

EntityBase {
        id: bullet
        entityId: "entity"
        entityType: "bullet"

        property int radius: 4
        property point initialImpulse: Qt.point(0, 0)
        property Team team

        CircleCollider {
                id: collider
                // ...
                linearDamping: 0.1 // make the bullet slow down overtime
                categories: team.bulletCategory
                collidesWith: team.bulletCollisionCategories
                // ...
        }

        // ...
}

And finally we add a shoot function to the Player entity. Here we first calculate the direction, which is a vector from the player position to the position of the crosshair (which is at the mouse cursor). After we've got the direction, we normalize it, scale it by the impulse constant and finally use the createEntityFromUrlWithProperties method of the entityManager to create a bullet entity while passing the initial values for the properties we are interested in.

Note that when creating a new bullet we pass the same team the player has, to the bullet.

Player {
        id: player

        // ...

        function shoot() {
                let directionX = crosshair.x - player.x
                let directionY = crosshair.y - player.y

                let directionLength = Math.sqrt(directionX * directionX + directionY * directionY)
                if (directionLength <= 0.0001) {
                        // The mouse cursor is almost exactly at the middle of the player, thus there is a chace
                        // of a division by zero.
                        return;
                }

                directionX /= directionLength;
                directionY /= directionLength;

                let impulse = 150;

                entityManager.createEntityFromUrlWithProperties(
                        Qt.resolvedUrl("./Bullet.qml"),
                        {
                                "x": player.x + sprite.width * 0.5,
                                "y": player.y + sprite.height * 0.5,
                                "initialImpulse": Qt.point(directionX * impulse, directionY * impulse),
                                "team": player.team
                        }
                );
        }
}

To quickly test how everything works we can temporarily call shoot whenever we get the pressed signal in the mouseArea:

MouseArea {
        id: mouseArea
        enabled: true
        // ...
        onPressed: (event) => {
                player.shoot();
        }
        // ...
}

This is not exactly what we initially intended, but we can quickly see how everything works. Right now shoot will only be called when the butten gets pressed, so you will need to press it multiple times to shoot many bullets.

Now that we've verified that it works, we can finish this features. The goal was to be able to press and hold to shoot bullets continuously. For that we will add a Timer to our player. The timer will periodically call the shoot function. And we will control it (enable or disable) whenever we get pressed or released signals from the mouseArea.

Player {
        // ...
        property int shootInterval: 200
        // ...
        Timer {
                id: shootTimer
                repeat: true
                running: false
                interval: shootInterval
                onTriggered: {
                        shoot();
                }
        }

        function startShooting() {
                shootTimer.restart();
        }

        function stopShooting() {
                shootTimer.running = false;
        }

        function shoot() {
                // ...
        }
}

Back in the mouseArea signal handlers we will call the new startShooting and stopShooting functions:

MouseArea {
        // ...
        onPressed: (event) => {
                player.startShooting();
        }
        onReleased: (event) => {
                player.stopShooting();
        }
}

And that is pretty much it, for this mechanic.

Damagable Component

Before we dive into implementing enemies we need to prepare some more common building blocks. Besides the Team being common between both the player and the enemies, one more thing they share is health. So here we will add exactly that. Health in our game will be reperesanted/handled by the Damagable component.

This a rather simple component and doesn't require much code. It will have a single function for appling damage and a couple of signals to notify the outside world:

import QtQuick
import Felgo

// This component implements health tracking + damage handling
//
// Can be shared by both the player and the enemies
Item {
        property Team team
        property int health
        property int maxHealth

        Component.onCompleted: {
                health = maxHealth
        }

        signal damageApplied(damage: int)
        signal death

        function applyDamage(damage) {
                if (health == 0) {
                        // Already dead => early return here, to avoid emitting `death` signal one more time.
                        return;
                }

                // Clamp the damage, so that the health doesn't become negative
                //
                // Also when reporting damage to the event system, we want to
                // send the actual damage amount that was applied
                if (damage > health) {
                        damage = health
                }

                if (damage > 0) {
                        health -= damage;
                        damageApplied(damage);
                }

                if (health == 0) {
                        death()
                }
        }
}

We can add this component to our player, while also exposing it through the damagable property:

Player {
        // ...
        property alias damagable: myDamagable

        // ...

        Component.onCompleted: {
                damagable.team = team
        }

        Damagable {
                id: myDamagable
                maxHealth: 6
        }

        // ...
}

Now the player has health, however we can't see how much of it is currently left, so we will add a little UI for that. The UI will be rather simple and just be a row of either full or empty hearts. Two Repeaters will do the trick.

The first repeater will place damagable.health number of full hearts and the other one will place damagable.maxHealth - damagable.health number of empty hearts.

We start by creating a new file under qml/ui

import QtQuick
import Felgo

import "../components"

Item {
        id: self
        property Damagable damagable
        property url fullHeartImage: Qt.resolvedUrl("../../assets/entities/heartFull.png")
        property url emptyHeartImage: Qt.resolvedUrl("../../assets/entities/heartEmpty.png")

        x: 0
        y: 0
        height: 16
        width: parent.width

        Row {
                width: parent.width
                height: parent.height
                Repeater {
                        model: damagable.health
                        Image {
                                source: self.fullHeartImage
                                fillMode: Image.PreserveAspectCrop
                                width: 32
                                height: 32
                                smooth: false
                        }
                }
                Repeater {
                        model: damagable.maxHealth - damagable.health
                        Image {
                                source: self.emptyHeartImage
                                fillMode: Image.PreserveAspectCrop
                                width: 32
                                height: 32
                                smooth: false
                        }
                }
        }
}

And finally add it to the scene:

import "./ui"

Scene {
        // ...

        Player {
                // ...
        }

        MouseArea {
                // ...
        }

        PlayerHealthBar {
                damagable: player.damagable
        }
}

BulletEmitter Component

One last thing we have to tackle here, is extracting creation of bullets into its own component.

This component will be called a BulletEmitter and will provide some common logic and make it easier for us to implement different attack patterns.

The process for adding a new component is already well-known. Here we pretty much want to extract the code we already have in the player entity, into a new place, with some minor adjustments: the bullets will be emitted relative to some "origin" entity. The users of this component will need to provide the initial position of the bullet relative to that origin. Most likely the origin will be the player or the enemy itself.

Here we have a code snippet extracted from the Player.qml:

import QtQuick
import Felgo

Item {
        id: self
        property Team team
        property url bulletPrefab
        property Item emissionOrigin
        property point emissionOriginOffset: Qt.point(0, 0)

        // Here `positionX` and `positionY` are local to the `emissionOrigin` entity
        function emit(positionX, positionY, directionX, directionY, impulse) {
                let forceVector = Qt.point(directionX * impulse, directionY * impulse)

                entityManager.createEntityFromUrlWithProperties(
                        bulletPrefab,
                        {
                                "x": positionX + self.emissionOrigin.x + self.emissionOriginOffset.x,
                                "y": positionY + self.emissionOrigin.y + self.emissionOriginOffset.y,
                                "initialImpulse": forceVector,
                                "team": self.team
                        }
                );
        }
}

In Player.qml we can now replace everything related with the BulletEmitter:

Player {
        // ...

        Component.onCompleted: {
                damagable.team = team

                // The `Bullet`s require a `Team` instance. `BulletEmitter` passes one to every created
                // bullet.
                bulletEmitter.team = team
                // Set the center of the player as the bullet emission origin.
                bulletEmitter.emissionOrigin = player
                bulletEmitter.emissionOriginOffset = Qt.point(sprite.width * 0.5, sprite.height * 0.5)
        }

        // ...

        TwoAxisController {
                // ...
        }

        BulletEmitter {
                id: bulletEmitter
                bulletPrefab: Qt.resolvedUrl("Bullet.qml")
        }

        // ...
}

And in the shoot function of the Player we replace entityManager.createEntityFromUrlWithProperties with bulletEmitter.emit:

Player {
        // ...
        function shoot() {
                // ...

                let impulse = 150;

                // Since the origin entity and the offset in `BulletEmitter` are set to the center of
                // the player, the initial position of the bullet is (0, 0).
                bulletEmitter.emit(0, 0, directionX, directionY, impulse);
        }
}

Enemies

Now we've reached the last major part of this tutorial and the game: the enemies. In the next sections we won't go into as much of details as in the previous ones, since we already have the majority of building blocks in place, and right now we will mostly need to assemble them.

As a part of this tutorial we will create a single enemy, which will be a ghost.

Enemy Entity

We start of as usual by creating a new entity file. The majority of it can be inherited from the Player, specifically: Damagable, CircleCollider and BulletEmitter (which will come in handy later).

After taking parts of the player and applying some minor modifications like changing the maxHealth and the sprite, and handling death signal of the Damagable, we end up with something like this:

import QtQuick
import Felgo
import "../components"

EntityBase {
        id: self
        entityId: "entity"
        entityType: "ghost"

        property alias damagable: myDamagable
        property Team team

        Component.onCompleted: {
                bulletEmitter.team = team
                damagable.team = team
        }

        Damagable {
                id: myDamagable
                maxHealth: 4
                onDeath: {
                        self.destroy();
                }
        }

        BulletEmitter {
                id: bulletEmitter
                emissionOrigin: self
                bulletPrefab: Qt.resolvedUrl("./Bullet.qml")
                emissionOriginOffset: Qt.point(sprite.width * 0.5, sprite.height * 0.5)
        }

        CircleCollider {
                id: collider
                categories: team.entityCategory
                collidesWith: team.entityCollisionCategories
                radius: 16
                fixedRotation: true
                linearDamping: 1

                Image {
                        id: sprite
                        anchors.centerIn: parent.anchors.center
                        smooth: false
                        source: Qt.resolvedUrl("../../assets/entities/ghost.png")
                        width: 32
                        height: 32
                        mirror: collider.linearVelocity.x < 0
                }
        }
}

And we can quickly add it to the scene:

Ghost {
        x: levelBackground.levelWalls.x + levelBackground.levelSize / 2
        y: levelBackground.levelWalls.y + levelBackground.levelSize / 4
        team: enemyTeam
}

Now if you were to launch the game and test the enemy, you would notice that the enemy doesn't seem to recieve any damage and moreover seems to be immortal. The reason for that is rather simple: we forgot to implement one tiny but crucial feature of the Bullet. Right now when a bullet hits an entity it doesn't apply any damage. It simply destroys itself.

Let's fix that. The fix is pretty straightforward. The one thing we need to keep in mind, is that if the entity and the bullet are on the same Team we don't apply the damage.

EntityBase {
        id: bullet
        entityId: "entity"
        entityType: "bullet"

        // ...

        CircleCollider {
                // ...
                fixture.onBeginContact: (other, normal) => {
                        let target = other.getBody().target;
                        let damagable = target.damagable;

                        // The bullet might have hit some other entity like a wall, that doesn't have a
                        // `Damagable` component.
                        if (damagable !== undefined) {
                                if (damagable.team === bullet.team) {
                                        // The entity is one the same => don't apply any damage and don't destroy
                                        // itself.
                                        return;
                                }

                                // To keep it simple apply a hardcoded damage amount. You might, however, want
                                // to make it configurable, if you want to extend the game even further.
                                damagable.applyDamage(1);
                        }

                        bullet.destroy();
                }
        }

        // ...
}

Now we can launch the game and verify that the enemy is indeed no longer immortal.

Making Enemies shoot

After creating a base for our enemy, we can start implement its attacks. For now we will keep it simple, and make it periodically shoot bullets. This is where we will need the BulletEmitter.

This doesn't require much. We just need a single timer, that will periodically fire (for example, every 1.2 seconds) and trigger the attack pattern.

There is also one problem we quickly need to take care of. We don't know where the player in the world is. To be able to shoot bullets in the direction of the player, we need to know the exact position.

Although we don't necessarily need the reference to the target right now for this attack pattern, we, however, will need it a bit later. So we are better off adding it right now, to not forget.

At this point, there are many options to handle this. For example, we could use colliders to check whenever a potential target is in range. However, we will go with a way simpler solution. In our case the only entity on the player's team is the player, there are no other players. That means, all the possible options for which entity could be a target, boil down to just the player. That said, we can simply pass the player instance from scene down to each enemy.

That what the target property in the Ghost.qml is for.

EntityBase {
        // ...

        property EntityBase target

        // ...

        Timer {
                id: attackTimer
                interval: 1.2 * 1000
                repeat: true
                running: true
                onTriggered: {
                        // attack pattern goes here
                }
        }
}

Back in the scene:

Ghost {
        // ...
        target: player
}

Now we can dive into implementing the actual attack pattern. We can start with a rather simple one, which involes shooting some number of bullets in all directions. Let's say that number is 12 bullets and they will be evenly spaced across the circumference of the circle.

The math for this is dead simple:

Timer {
        id: attackTimer
        // ...
        onTriggered: {
                let count = 12;
                let angleStep = 2 * Math.PI / count
                for (let i = 0; i < count; i += 1) {
                        let angle = angleStep * i;

                        let x = Math.cos(angle);
                        let y = Math.sin(angle);

                        bulletEmitter.emit(0, 0, x, y, 150);
                }
        }
}

This was pretty neat, however I want to give an example of a more sofisticated attack pattern. This attack pattern involves shooting bullets directly towards the player, while applying some variation in direction and creating bullets one by one with some time in between.

This pattern is already at the limits of what the current BulletEmitter allows. It allows us to immediately create bullets. However, we want quite the opposite. We could add another timer to the Ghost enemy, that delays the creation of bullets, but it would complicate things. Furthermore, we want to keep it reusable so that other pattern implementation could benefit from it.

The idea here is to introduce a queue and a Timer in the BulletEmitter. The timer will fire periodically and pop an entry from the front of the queue and spawn a bullet. And in the enemy attack implementation we will simply push bullet entries to the end of the queue.

The modifications to the BulletEmitter look like this:

Item {
        // ...
        property point emissionOriginOffset: Qt.point(0, 0)

        property var queue: []

        Timer {
                running: true
                interval: 100
                repeat: true
                onTriggered: {
                        if (queue.length === 0) {
                                return;
                        }

                        let first = self.queue.shift();
                        emit(first.x,
                                first.y,
                                first.directionX,
                                first.directionY,
                                first.impulse);
                }
        }

        function enqueueForEmission(positionX, positionY, directionX, directionY, impulse) {
                self.queue.push({
                        "x": positionX,
                        "y": positionY,
                        "directionX": directionX,
                        "directionY": directionY,
                        "impulse": impulse
                })
        }

        // Here `positionX` and `positionY` are local to the `emissionOrigin` entity
        function emit(positionX, positionY, directionX, directionY, impulse) {
                // ...
        }
}

And now we are ready to implement our new sofisticated attack pattern. The code for this pattern is actually quite similar to the first one we had. What changed is how we compute the angle. Before we just used to evenly space things out across the circumference. However, right now we use atan2 to compute the angle between the X axis and the direction towards the player. Then, when spawning bullets, we apply a random jitter to that angle, and use our newly created enqueueForEmission.

EnemyBase {
        // ...

        function randomInRange(min, max) {
                let value = Math.random();
                return min + value * (max - min)
        }

        Timer {
                // ...
                onTriggered: {
                        let dx = target.x - self.x
                        let dy = target.y - self.y
                        let angleTowardsTarget = Math.atan2(dy, dx)

                        let spread = Math.PI / 6;
                        let count = 4;
                        for (let i = 0; i < count; i += 1) {
                                let spreadAngle = randomInRange(-spread / 2, spread / 2)
                                let angle = angleTowardsTarget + spreadAngle

                                let x = Math.cos(angle);
                                let y = Math.sin(angle);
                                bulletEmitter.enqueueForEmission(0, 0, x, y, 150);
                        }
                }
        }
}

Our new attack pattern is done. Although, we had to get rid of the first one, we can still use it in a different place. For example, whenever the enemy dies, this shouldn't be that difficult to implement. We only have to move the pattern code to the death signal handler, where we already have self.destroy().

Damagable {
        id: myDamagable
        maxHealth: 4
        onDeath: {
                let count = 12;
                let angleStep = 2 * Math.PI / count
                        for (let i = 0; i < count; i += 1) {
                                let angle = angleStep * i;

                                let x = Math.cos(angle);
                                let y = Math.sin(angle);

                                bulletEmitter.emit(0, 0, x, y, 150);
                        }

                self.destroy();
        }
}

That is pretty much it. We can now test our enemy.

Enemy State Machine

And finally, the last thing we will tackle in this tutorial is a simple enemy AI, since right now the enemy, besides the attacks, doesn't do much. The AI will be a state machine with only 2 states: attacking and following. In terms of the attack state, there isn't much, as we've already implemented it and will only need to port it to work with the state machine. That means, we are left with implementing the state machine and the following state.

The following state isn't complicated either, it simply involves moving the enemy towards the player, until it is in range. When in range we switch the enemy into the attacking state.

To implement our state machine, we will start with the next modifications to our enemy code. Here we will turn on and off the attackTimer whenever the enemy enters/leaves the attacking state.

EntityBase {
        // ...
        state: "follow"
        states: [
                State {
                        name: "follow"
                        PropertyChanges { target: attackTimer; running: false }
                },
                State {
                        name: "attack"
                        PropertyChanges { target: attackTimer; running: true }
                }
        ]
}

We will also need to run some code every frame. For example, every frame we will check whether the target is still in range and also try to move the enemy towards the target.

That will be taken care of by a Timer that runs every 16ms (assuming we are running at 60 frames per second).

Timer {
        id: updateTimer
        interval: 16
        running: true
        repeat: true
        onTriggered: {
                // Here we update the whole state machine of this enemy

                switch (state) {
                case "attack":
                        // Actual bullet emission is ran on its own timer
                        //
                        // So here we only have to check, whether the target is still in range
                        if (!isTargetWithinRange()) {
                                // No target in range, go back to following
                                state = "follow"
                        }

                        break;
                case "follow":
                        if (isTargetWithinRange()) {
                                // The target is in range, the enemy can start attacking.
                                state = "attack";
                        } else {
                                // The target is not in range.
                                //
                                // Move towards it.
                                let dx = target.x - self.x
                                let dy = target.y - self.y
                                let distanceToTarget = Math.sqrt(dx * dx + dy * dy)

                                // Normalize the direction
                                dx /= distanceToTarget;
                                dy /= distanceToTarget;

                                let speed = 80
                                collider.linearVelocity = Qt.point(dx * speed, dy * speed);
                        }

                        break;
                }
        }
}

And also add the helper function isTargetWithinRange:

EntityBase {
        // ...
        property int attackRange: 220

        // ...

        // This is this a simple distance check.
        function isTargetWithinRange() {
                let dx = target.x - self.x
                let dy = target.y - self.y
                let distanceToTarget = Math.sqrt(dx * dx + dy * dy)
                return distanceToTarget <= attackRange;
        }
}

And these were the final changes, we need to make to get the state machine working. Now we have a fully working enemy with two state and two distinct attack patterns.

Conclusion

After following this tutorial you will end up with a pretty solid base for a game in a Bullet Hell genre.

Here we went through implementing player controls, bullet mechanics and shooting, an enemy, its state machine and attack patterns. Besides that, this tutorial describes how all the game components were created in way that allows, to assemble them without much problems to create new entities, enemies and their attack patterns.

This game, however, still lacks some features, like:

  • a main menu
  • game over and restarting logic
  • spawning of waves
  • sound effects

But with the current foundation it should be much easier to expand the game further. As an example, you can checkout the GitHub repository. It contains a more complete version of the game, then the one described in this tutorial.
