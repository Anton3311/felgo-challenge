Bullet Hell Game Tutorial using Felgo

Introduction

This tutorial describes how to create a simple 2D Bullet Hell Game using Felgo.

The tutorial will provide a base for the overall game, enabling anyone to further expand on it. Here we will go in details on how to implement the player controls and shooting mechanics, enemies, their state machines and attack patterns, wave spawning and scene management.

The source code for the finished project is available on GitHub

Assets

The art assets used throughout this tutorial are from Kenney and are available here under CC0 1.0 License. This asset pack doesn't cover all of the needed art, thus some of the missing pieces were hand-drawn in the same style. All of the used art assets are available in GitHub Repository under assets/entities

The pixel font used in the game is available on Google Fonts

Project Setup

Start by creating a new Felgo Games project in Qt Creator. Sepcifically we will need New - Empty Felgo Project template. The created project will already contain some example code in the Main.qml, which we will reduce down to these 15 lines:

import Felgo 4.0
import QtQuick 2.0

GameWindow {
        id: gameWindow
        activeScene: scene
        screenWidth: 960
        screenHeight: 640

        Scene {
                id: scene
        }
}

Player Controls

As the first major step, we will start with the player controller, to get at least something moving on the screen. But before we dive into coding a player control, we need to prepare out scene.

Firstly our player is an entity, and to be able to work with entities, our scene needs an entity manager. So we add one:

// This `Item` serves as a container for all entities. Any entities created during the game,
// will be added to this container.
Item {
        id: level
}

EntityManager {
        id: entityManager
        entityContainer: level
}

Now that, we have an entity manager, we can start creating our player.

The code for the player will live in qml/entities/Player.qml.

import QtQuick
import Felgo

EntityBase {
        id: player
        entityId: "entity"
        entityType: "player"

        Image {
                id: sprite
                // Place the player sprite right in the center of the entity
                anchors.centerIn: parent.anchors.center
                // Disable smoothing to keep the pixel art crisp.
                smooth: false
                source: Qt.resolvedUrl("../../assets/entities/player.png")
                width: 32
                height: 32
        }
}

And then in our Main.qml we will first import the code from entities folder:

import Felgo 4.0
import QtQuick 2.0
import "./entities"

Finally add our Player right after the EntityManager, like this:

Scene {
        id: scene

        EntityManager {
                id: entityManager
                entityContainer: level
        }

        Player {}
}

Now lets move onto player controls. Out will rely on physics, that means we first need to setup a PhysicsWorld:

Scene {
        id: scene

        EntityManager {
                id: entityManager
                entityContainer: level
        }

        PhysicsWorld {
                id: physicsWorld
                gravity.y: 0
                updatesPerSecondForPhysics: 60
                velocityIterations: 5
                positionIterations: 5
                debugDrawVisible: false
        }

        Player {}
}

Now that we have the PhysicsWorld, we can add a collider to our player. We will also make our player sprite a child of the collider. The resulting player code looks like this:

CircleCollider {
        id: collider
        radius: 16
        // Disable rotations caused by collisions.
        fixedRotation: true

        Image {
                id: sprite
                anchors.centerIn: parent.anchors.center
                smooth: false
                source: Qt.resolvedUrl("../../assets/entities/player.png")
                width: 32
                height: 32
        }
}

The final step before player is able to move around the scene, is the actual keyboard controls. Here we will use a TwoAxisController with our 4 movement directions mapped to WASD keys.

TwoAxisController has two property we are interested in: xAxis and yAxis.

We can use them to provide a velocity vector for the CircleCollider like this:

linearVelocity: Qt.point(axisController.xAxis, axisController.yAxis)

TwoAxisController is only able to notify us about, whenever a button gets pressed or release. However, we want to be able to presss and hold a button to move in a desired direction. This requires a bit more bookkeeping. We will need to keep track of which of the 4-direction keys are currently pressed and update that state on each press/release together with manually updating xAxis and yAxis properties of the controller.

Add the bool properties, corresponding each of the movement directions, at the start of the Player entity:

property bool isMovingLeft
property bool isMovingRight
property bool isMovingUp
property bool isMovingDown

Out TwoAxisController we will lok like this:

TwoAxisController {
        id: axisController
        onInputActionPressed: (actionName) => {
                updateActionState(actionName, true);
                updateMovementAxis();
        }
        onInputActionReleased: (actionName) => {
                updateActionState(actionName, false);
                updateMovementAxis();
        }
        inputActionsToKeyCode: {
                "up": Qt.Key_W,
                "down": Qt.Key_S,
                "left": Qt.Key_A,
                "right": Qt.Key_D
        }
}

Also don't forget to add the speed property to the player entity:

property int speed: 150

And finally the helper functions for state tracking and updating controller properties:

function updateActionState(actionName, value) {
        if (actionName === "up") {
                isMovingUp = value
        }

        if (actionName === "down") {
                isMovingDown = value
        }

        if (actionName === "left") {
                isMovingLeft = value
        }

        if (actionName === "right") {
                isMovingRight = value
        }
}

function updateMovementAxis() {
        let dx = 0;
        let dy = 0;

        if (player.isMovingUp) {
                dy -= 1;
        }

        if (player.isMovingDown) {
                dy += 1;
        }

        if (player.isMovingLeft) {
                dx -= 1;
        }

        if (player.isMovingRight) {
                dx += 1;
        }

        if (dx === 0 && dy === 0) {
                axisController.xAxis = 0;
                axisController.yAxis = 0;
        } else {
                let deltaVectorLength = Math.sqrt(dx * dx + dy * dy);
                let deltaScale = 1 / deltaVectorLength * player.speed;

                axisController.xAxis = dx * deltaScale;
                axisController.yAxis = dy * deltaScale;
        }
}

One more final touch. We can set the mirror property of the Image to be computed based on the horiontal speed, so the player sprite gets mirrored when the player moves left.

mirror: collider.linearVelocity.x < 0

For the whole player controller to work, we also need to forward all of the key events from the scene to our TwoAxisController. For that we will first need expose the TwoAxisController inside the player to an outside world, by creating an alias property:

EntityBase {
        id: player
        entityId: "entity"
        entityType: "player"

        property int speed: 150
        property bool isMovingLeft
        property bool isMovingRight
        property bool isMovingUp
        property bool isMovingDown

        // Expose the controller to an outside world
        property alias controller: axisController
        ...

And forward the events by adding this code in our Main.qml:

Keys.forwardTo: [player.controller]

Player {
        id: player
}

At this point the player should be able to move around the screen.

Level

Now that we have a moving player, we can add level for the player to move around. Here we will with a rather simple design, the whole level wil be a square-shaped arena.

The whole level will be its own entity and is built out of tiles from the asset pack.

The code for it rather straightforward:

import QtQuick
import Felgo

Item {
        property int levelSize: 176 * 2
        property int wallThickness: 30
        property int wallCategory: Fixture.Category1

        property alias levelWalls: walls

        // Fill the whole screen with a solid color matching the borders of the background sprite
        Rectangle {
                anchors.fill: parent
                color: "#763b36"
        }

        EntityBase {
                // Display the level background below everything
                id: walls
                width: levelSize
                height: levelSize
                anchors.centerIn: parent

                // Top
                BoxCollider {
                        // Move the top one down a bit, so that it covers the top wall
                        y: 16
                        width: parent.width; height: wallThickness
                        bodyType: Body.Static
                        categories: wallCategory
                }

                // Down
                BoxCollider {
                        y: levelSize - wallThickness
                        width: parent.width; height: wallThickness
                        bodyType: Body.Static
                        categories: wallCategory
                }

                // Left
                BoxCollider {
                        width: wallThickness; height: levelSize
                        bodyType: Body.Static
                        categories: wallCategory
                }

                // Right
                BoxCollider {
                        x: levelSize - wallThickness
                        width: wallThickness; height: levelSize
                        bodyType: Body.Static
                        categories: wallCategory
                }

                Image {
                        smooth: false
                        width: levelSize
                        height: levelSize
                        source: Qt.resolvedUrl("../../assets/entities/levelBackground.png")
                }
        }
}

The colliders here a placed to match where the walls are in the background sprite. If you set debugDrawVisible to true in the PhysicsWorld you will see the next picture:

Then we add it to out scene and also set z to some negative value, so that is appears under everything in the scene:

LevelBackground {
        id: levelBackground
        z: -100
        anchors.fill: scene
}

Now, if you run the game, you will notice, that the player is stuck outside of the level. To fix this, we will change the default Player position to be roughly in the middle of the level:

Player {
        id: player
        x: levelWalls.x + levelBackground.levelSize / 2
        y: levelWalls.y + levelBackground.levelSize / 4 * 3
}

And now, were done with the level part and can move onto other parts of the game.

Bullets and Shooting

Now the fun part. Here we will finaly start adding bullets, because a bullet hell game without the bullets and bullet patterns isn't a bullet hell.

In this part, we will design reusable components for us to later be able to implement different bullet patterns for the enemies. For example, some of the patterns, we will have at the end look like this:

First we will start by creating a new entity. A Bullet:

import QtQuick
import Felgo

EntityBase {
        id: bullet
        entityId: "entity"
        entityType: "bullet"

        property int radius: 4
        property point initialImpulse: Qt.point(0, 0)

        CircleCollider {
                id: collider
                radius: bullet.radius
                bodyType: Body.Dynamic
                groupIndex: -1 // make sure that bullets never collide with each other
                linearDamping: 0.1 // make the bullet slow down overtime
                fixedRotation: true
                fixture.onBeginContact: (other, normal) => {
                        // On collision with anything - destroy
                        bullet.destroy();
                }

                Image {
                        smooth: false
                        anchors.centerIn: parent
                        source: Qt.resolvedUrl("../../assets/entities/bullet.png")
                        width: 32
                        height: 32
                }
        }

        Component.onCompleted: {
                collider.applyLinearImpulse(initialImpulse, collider.body.getWorldCenter())
        }
}
